# Phase 1 - Review the content before laying it out

Goal: the user decides what text goes into the layout before any design work
starts. Laying out a draft with problems multiplies the fixes later.

## What to look for

Read the whole Word file (and any other text the user sends) and check:

1. **Repeated versions.** Drafts often hold two or three versions of the same
   text one after another (several introductions, two conclusion blocks, the
   same idea in different words). Map them: which sections repeat, which
   version is fullest, what each one has that the others lack.
2. **Claims that need a source.** Market claims ("no one else does this"),
   comparisons with named competitors, regulations, figures. Mark the ones
   that are not verified and propose softer wording or a source. Do not
   assert that a claim is false without checking it either.
3. **Figures.** If the reference uses key-figure boxes and the content has no
   figures, never invent them. Propose qualitative boxes, or a marked gap for
   a real figure with its source.
4. **Content from another document or product.** Text, names, contacts or
   calls to action copied from a previous piece (a closing page that names
   another product, a contact person from another team).
5. **Missing pieces the layout will need.** Closing call to action, contact
   people (name, role, email, photo), sources, captions.
6. **Small errors** worth fixing before layout: missing full stops, broken
   emphasis, inconsistent terms, a title that differs from the file name.

## How to report it

- Short summary of what you found, grouped as above.
- For decisions (consolidate the versions or keep them, soften a claim),
  list the options with the cost of each, recommend one, and ask. Never pick
  silently.
- When you consolidate, keep a list of what was merged and what was left
  out, and hand it over with the layout.
- Any text you write (titles, box texts, captions, questions for an FAQ)
  is marked as yours so the user validates it.

## Screenshots and images that come with the content

Before proposing to use them, check:

- **Real data:** customer names, plant or site names, IPs, people, serial
  numbers. Ask whether it is demo data; if it is real customer data it cannot
  go into a public document.
- **Third-party licences:** map imagery, stock photos, other companies'
  interfaces. Say what needs checking.
- **Language:** a screenshot in another language than the document.
- **Resolution:** the effective ppi at the size it will print (pixels x 72 /
  width in pt). Below about 200 ppi, say so.
